# Live policy runtime

`config/live-policy.example.json` is strict declarative JSON. Its top-level shape is exactly `schemaVersion` and `rules`. A rule has an identifier, `block` or `normal` safety class, integer priority, finite weight of at least one, finite predicates, and a bounded command sequence. It accepts only a finite allow-list of observation fields, comparators and reviewed command IDs; JavaScript, selectors, URLs and costs are rejected.

Safety blocks win first. Remaining rules are ordered by descending integer priority and finite weight, with JSON order as the final tie-break. Each sequence step receives a fresh observation and stops on a failed, skipped or ambiguous outcome. `live run --once --dry-run` uses the same planner and makes no command.

Command cost is immutable adapter metadata. Reviewed commands currently cover `hero.encourage` in field/dungeon, `hero.restore_prana`, dungeon entry/navigation, polygon entry and a constrained polygon push, and ZPG start. Polygon entry requires 80 prana to retain a 30-prana two-step reserve; a polygon push requires 15 prana and is limited to a reviewed adjacent repair kit or bit. JSON cannot lower those costs or authorize charge handling. A live command requires a configured single-account identity and an adapter-derived stable event ID. The final snapshot must retain the command's allowed mode and stable identity; dungeon navigation additionally requires the same battle turn. ZPG targets the opening of each hour and its physical gate is bounded to the configured `5..160`-second window, always before the official three-minute limit. An intent hashes the fixed command, hero and event, without a policy rule ID, so renaming JSON rules cannot enable a duplicate click. An ambiguous prior operation remains blocked by command ID.

The adapter invokes the runner's journal gate only after its bounded reaction delay and final DOM recheck. The runner then re-evaluates the JSON policy, verifies the immutable command metadata, persists the final observation and decision, checks its shared browser lease, and atomically records the operation. Ambiguity is never retried.

The runner is adapter-neutral. The Orca adapter is host-only and requires an already-open Orca page; browser-runtime/Playwright remains a separate optional runtime and does not provide the live Orca adapter. `live run` is a continuous host loop and preserves/reconciles durable ZPG lifecycle state across restart. Active polygon pushes are implemented only under the constrained rule above. Sailing, inventory activation, arbitrary boss actions, and unknown server confirmation prompts are unsupported. The application runs on Bun 1.4.2; `browser.Dockerfile` provides the optional Chromium image.
